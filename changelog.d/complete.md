## Fixed

- Every resource page now lists exactly the attention signals its type ships, with the colour, the glyph and the surfaces the app actually gives them. Sixty-five pages promised something else: a certificate page listing `revoked` when the app says `<status, in words>`, an API Gateway page describing one signal out of seven, an EBS page calling a broken volume a warning, and three hundred and twenty rows telling the reader a yellow or red row stays out of the menu issue count when it is exactly what the count is made of.
- The rule for which surfaces a signal reaches is now written once, in the signals reference, instead of being restated on all seventy pages in wording that had drifted from the app. Each page cites it and names the surfaces per signal.
- Nineteen rows claimed a signal has no finding behind it while the app registers one. A KMS key that is creating or updating is a red row reading its key state, not a yellow rotation warning. A web ACL that allows everything with no rules is on the backlog list, not a shipped signal. An ECR repository with high-severity findings and no critical ones reaches the menu count like any other broken row.
- A signal a page marks "not implemented" is now recorded once, on the signals reference's own backlog list, in one wording. ECR's scan-on-push warning ships today, and the CloudFront, Secrets Manager and Subnet deferrals now say the same thing the reference says.
