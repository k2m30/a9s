## Cost Explorer — Why Am I Spending That Much?

### The spend grid that matches your invoice

- `:costs` / `:ce`, `a9s -c costs`, or the main-menu entry opens AWS spend as
  a grid: services in rows, months in columns, invoice-mode amounts in cells —
  column totals match the AWS invoice to the cent (verified live against
  `GetCostAndUsage`).
- Cells color by period-over-period change with a neutral band, so a doubled
  bill stands out in strong color while routine wiggle stays quiet. Cost
  anomalies mark their cells and put the root cause with its dollar impact in
  the footer.
- Pivot rows by service, region, linked account, usage type, purchase option,
  or charge category (`1`-`6`; `0` resets). Cycle five cost metrics with `b` —
  invoice, unblended, amortized, net amortized, blended.
- Zoom the time axis from years to months, weeks, and days (`+`/`-`), anchored
  at the cursor. Scroll left past the oldest column to fetch older history, up
  to the Cost Explorer 13-month horizon.

### Drill from a number to the machine behind it

- `Enter` on any cell narrows to that row and period at a finer granularity:
  service → usage type → (last 14 days, EC2) the individual instances — and
  one more `Enter` opens the standard resource detail view with its related
  panel. `Esc` walks back exactly.
- Accounts without the resource-level opt-in get AWS's own explanation in the
  footer instead of an error screen; services AWS can't break down to
  resources say so honestly.
- Region-less charges ("NoRegion" — tax-like items) drill correctly, and a
  drill whose finer granularity has no records falls back once to the parent
  granularity instead of rendering silent zeros.

### Fetched once, cached honestly

- Closed months are fetched once and cached on disk per profile — restarts
  render instantly and offline. The open month refreshes on a 24-hour TTL;
  `Ctrl+R` forces it. A month cached mid-month refetches after the calendar
  rolls over, with a settlement grace for AWS's own data revisions.
- Every Cost Explorer API request costs $0.01 — the fetch planner asks only
  for what the cache can't answer, and a skipped fetch can never masquerade
  as authoritative data (an anomaly-only refresh can't touch cost rows, and
  vice versa).
- `--no-cache` and demo sessions keep cost data in memory only.

### The same screen everywhere

- The web UI (`--web`) serves the identical grid with the identical keys; the
  terminal and browser lanes share one state machine, one computed view, and
  one typed failure path — enforced by a lane-parity test harness.
- Demo mode (`a9s --demo`, then `:costs`) ships a planted cost-spike story
  traceable end to end: the anomaly-marked cell, the usage type behind it,
  and the instance it belongs to.

### Under the hood

- Cost-screen decisions live in a pure domain state machine with typed
  outcomes (fetch plans, drill transitions, window constructors, money that
  keeps its currency until a total is proven single-currency). The full
  delivery matrix and two AST discipline gates are pinned in the suite.
- EC2 instances resolve by ID, so exact-ID drills from the related panel and
  the Cost Explorer land directly on the instance detail — and a stale ID in
  a batch can no longer degrade into an account-wide describe.
- IAM policy availability probes no longer time out on group-heavy accounts:
  the probe counts managed policies as an honest lower bound, and the inline
  sweep runs with bounded parallelism.
