# v3.53.2 — Patch

Honest degradation, refined. When a resource is listed but its per-item
details can't be fetched, a9s keeps a name-only row — but it no longer calls
every such failure "details denied." Only a genuine authorization denial
(including EC2's `UnauthorizedOperation` code, which the previous check
missed) reads **"details denied"**; a nil/empty response, a throttle, a
cancellation, or a row absent from a batch response now reads the neutral
**"details unavailable."** A not-found or transient failure never sends the
operator chasing an IAM policy that isn't the problem.

Applies across all seven types that keep degraded rows — MWAA, Transfer,
Launch Templates, DynamoDB, OpenSearch, EKS clusters, and node groups. Row
color, menu counts, and severity are unchanged; only the wording gets honest.

Also fixed: an EKS node group's related panel could pull EC2 instances or EBS
volumes from a *different* cluster that happened to share a node-group name,
when an instance's `eks:cluster-name` tag was absent — matching now requires an
exact cluster-tag match. Rounded out with a CodeRabbit pass over the
v3.49.1→v3.53.1 series: tighter test assertions and small fixture/code cleanups.
