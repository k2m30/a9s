# v3.55.0 — Non-functional hardening

A reliability, performance, and honesty release driven by a full
code-versus-docs review (34 adversarially verified findings) and three
external review rounds. No new resource types; the product gets faster,
harder to crash, and more truthful about what it knows.

## Reliability

- Fixed a fatal concurrent-map crash reachable by opening a list during
  the background enrichment sweep.
- Every interactive fetch — including server-side filtered drills — now
  carries a 30-second deadline: a dropped VPN or stalled SSO endpoint
  surfaces as a timeout instead of an eternal spinner.
- Switching profile or region cancels in-flight background probes instead
  of letting them burn AWS calls whose results would be discarded.
- EKS node groups: clusters whose node groups span multiple API pages no
  longer lose everything past page one, and a result-capped fetch resumes
  exactly where it stopped via a composite continuation token.
- A related-checker panic now lands in the error log with its cause
  instead of rendering a silent, permanent `?`.
- Theme saving can no longer destroy `config.yaml`: a corrupt or
  unreadable existing file aborts the save with a visible error, and
  writes are atomic (temp file + rename).
- The enrichment dispatcher survives its races: stale completions free
  their slot instead of starving the queue, a list-open probe can no
  longer trigger a duplicate sweep probe, and the progress badge cannot
  strand at N−1/N.

## Performance

- List rendering is memoized: a frame on a 3,000-row list dropped from
  7.3 ms to 72 µs (105,700 allocations to 16). Staleness is pinned by
  sequence tests across every cache-key input, including background
  row-store updates under a not-yet-adopted screen.
- Cache saves skip files whose content is unchanged, and disk writes
  moved outside the session-wide pair lock, so UI reads no longer queue
  behind file I/O on large accounts.
- Wave-2 enrichment dispatches through a bounded window of 4 concurrent
  probes with live refills, replacing the all-at-once burst of ~50.
- ACM enrichment no longer makes one API call per certificate: expiry and
  orphan findings come from the list call itself, which also removes a
  blind spot beyond the 50-certificate enrichment cap.

## Honest severities

Aligned with the attention-signals contract: a rolling deploy (some
targets still registering) renders yellow, not red; a bucket without full
public-access-block is a warning, not an outage; certificates use
graduated 30-day/7-day thresholds; EC2's four instance-status conditions
carry four distinct finding codes with their real severities. Four
related checkers that reported a confident zero on a cache miss now
honestly report unknown.

## Observability

New opt-in diagnostics: `--log-file` (or `A9S_LOG_FILE`) writes JSON
diagnostics to a file — off by default, the TUI keeps the terminal.
Probe failures and timeouts appear in the `!` error log, one entry per
type per sweep. Web mode logs requests and previously-discarded render
errors when the facility is enabled.

## Gates

The read-only guarantee is now checked on the AST (`cmd/readonlycheck`):
comments, strings, and formatting can no longer hide a write call. New
pre-push gates verify the renderer-free core boundary, installed git
hooks, and generated-doc freshness (`check-catalogen`); sensitive-term
scanning runs in the gate itself; arch-review carries a dead-export
baseline. Two drift-guard tests pin the process doc to the Makefile and
the attention-signals prose to its generated tables.

## Breaking for `core/` importers

- `IssueEnricherResult.IssueCount` and `messages.EnrichmentChecked.Issues`
  are deleted (dead: the badge authority was already the unified count).
- 24 dead exports removed, including superseded whole-page fetchers
  (`FetchEC2Instances`, `FetchS3Buckets`, `FetchEKSClusters`,
  `FetchKMSKeys`, ...) and `projection.Generic` (use
  `GenericWithConfig`); 17 test-only exports renamed to `*ForTest`.
- `cache.Store.SaveType` is now composed from `PrepareSave`/`CommitSave`
  (signature unchanged); `scripts/verify-readonly.sh` is gone.

## Docs

architecture.md, development-process.md, the codebase checklist, and the
attention-signals prose were reconciled with the code (the architecture
doc's directory tree, extension guide, and cache sections described a
deleted world) and are now pinned by the drift guards. The test suite
shed its session archaeology: defect-code and work-batch names replaced
by behavior-derived names across functions, fixtures, and 23 files, and
53 duplicate test fakes collapsed into canonical per-service fakes.
