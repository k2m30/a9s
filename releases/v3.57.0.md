# v3.57.0 — the row says what an auditor would ask

Until now a9s told you what a resource *is*: running, available,
pending deletion. This release makes every row also say what is
*wrong with it* the way a security audit would: the status cell, the
row colour and the detail view's Attention section all read from one
registered finding per condition, with a sentence saying what the
condition means for the workload and what to change.

## Posture checks across the catalogue

120 Prowler checks, named by ID in `CHANGELOG.md`, are closed on their
resource type's own row, plus the per-port security-group and EC2
exposure siblings. The breadth is the point: S3, EBS, RDS and Aurora,
DocumentDB, DynamoDB, ElastiCache, Redshift, OpenSearch, EFS, EC2
instances, AMIs, snapshots, launch templates, security groups, subnets,
VPC endpoints, transit gateways, load balancers, auto scaling groups,
ECS services and tasks, EKS, ECR, CodeBuild, Glue, Lambda, Step
Functions, SQS, SNS, MSK, Kinesis, SES, Elastic Beanstalk, CloudTrail,
CloudWatch, Route 53, CloudFront, ACM, API Gateway, IAM users, groups,
roles and policies, KMS, Secrets Manager, WAF and AWS Backup coverage.

Every check is read-only and every one is a finding: the wildcard
public-policy checks run on one shared policy engine (conditions that
only *look* scoping, GovCloud and China root principals, and
`IfExists`/negated operators are all handled once), the secret scanner
finds credentials in environment variables, user data, stack outputs,
job arguments and state-machine definitions without reporting a
Secrets Manager ARN or a `$VAR` reference as a leak, and a check that
could not run says so instead of calling the resource clean.

## Rows that admit what they do not know

A sweep inspects a bounded number of rows per type. Past that cap, a
row now reads `not inspected` and carries the reason, in the list and
the detail view, and the mark survives a restart. Opening such a row's
detail runs its checks on demand, and the answer is saved with the row.
Related-panel pivots follow the same rule: twenty-nine of them used to
report a confident zero when the list behind them was never read or
the call was denied; they now read as unknown, or as a lower bound
when only part of the list came back.

## Detail views fetch what the list cannot

Opening a detail, YAML or JSON view enriches on demand (#261): Step
Functions definitions, CloudFormation templates, Lambda deploy state,
decoded EC2 user data, SNS topic attributes, S3 policy, CORS and
lifecycle documents, IAM policy documents. A detail open runs under
one operation identity, so a refresh supersedes in-flight work instead
of racing it, and `--trace <path>` writes the operation's lifecycle as
JSON lines for diagnosis.

## The first screen explains itself

The start-up sweep now runs whichever of the on-disk cache and the AWS
connection lands first; when the cache won the race the terminal sat at
`verifying 0/70` with no counts for the whole session, which the live
read-only smoke in the release gate caught. The menu title counts the
sweep (`verifying 12/71`), a row
whose check was refused says `denied`, `expired`, `throttled` or
`error` in place of its alias, a whole-account failure is stated once
in the title, and the terminal's `refreshing…` line now clears when the
sweep finishes instead of staying for the session. Every status-bar and
error-log line reads the same way: what was being fetched, then why it
failed, with no request IDs or encoded authorization blobs.

## Web mode reaches parity

Detail enrichment, related-panel drill-ins, the `:profile`, `:region`
and `:theme` commands, `--no-cache -c <resource>`, and the demo's cache
all behave on the web page as in the terminal. Two web sessions on one
profile no longer tear each other's Cost Explorer cache save.

## Security fix

Switching profile or region could leave the previous account's caller
identity, a revealed secret value or its Cost Explorer figures on
screen under the new account's name, because one of the freshness
counters started at zero. Closed, with regression coverage for all
three.

## Also

View files in `~/.a9s/views/` are upgraded in place on start (your
widths and order kept); `docs/attention-signals.md` and every
`docs/resources/*.md` page are generated from the registered findings
and gate-pinned; `make check-deps` fails the push on dependency drift;
`make test-race` allows 900 seconds. Removed: the `!`/`~` row glyph
that could never appear, and the never-read new-since-last-scan counts.

## Review trail

Per-task Codex and CodeRabbit passes on each landed range (the
`codex*` and `views7_codex_rows` test files pin their findings), a
pre-release consistency audit of docs against code, a busywork audit
of the tests added in the range, and the live read-only smokes against
a real account before the tag.

## Retro

What slipped: the demo menu-count pin test
(`TestFourRules_Demo_R1_SpecificTypesShowIssueCounts`) was red on `main`
from 2026-09-06, when a secrets pin was written that never matched the
fixtures, to 2026-09-15, and a role fixture added on 2026-09-14 moved a
second pin without anyone seeing it. Why: the team-loop landing checklist
named the round gates (`go vet`, `make test`, `make lint`,
`check-catalogen`, `mdlint`, `security`) and not `make integration`, so
every landing in between passed its list while the process document's
Stage 6 gate never ran on a landing tree. Rule change, in this release:
landing step 4 of `.claude/skills/a9s-team-loop/SKILL.md` is
`make ready-to-push`, exit code read from captured output.
