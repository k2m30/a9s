## One Status Column, Findings-Derived Color

### Every list explains itself the same way

All 66 resource types now share one presentation contract:

- Exactly one status column, titled `Status`, on every list view. The
  duplicate `State`, `Issues`, `Risk`, `State Reason` and `Logging` columns
  are removed; `.a9s/views/*.yaml` regenerated.
- The Status cell renders the row's finding phrase first, else the
  humanized lifecycle state. No raw AWS enum reaches any rendered cell.
- Row color derives from the row's findings (worst severity wins). Color,
  Status text and the detail Attention block share one source, so a
  yellow or red row always names its cause on every surface.
- Finding phrases are operator sentences without benchmark citations:
  "deletion protection disabled", "reads sensitive data (ListSecrets)",
  "access key >90d old", "orphan: source volume deleted".

### Enforcement, not hope

- Color-vs-findings conformance gate with an empty allowlist: any
  classifier that colors a row without a finding fails the suite.
- Status-column uniformity gate: a second cause-bearing column is a
  failure.
- Dynamic witness gate: a registered finding that never fires on a demo
  fixture is a coverage hole.
- Demo smoke joined `make ready-to-push`; `make smoke-live` sweeps every
  non-empty type of a real readonly account for raw enums and vacuous
  statuses.

### Related panel

- 24 pivots that returned zero or garbage now implement their documented
  mechanisms (five new AWS API integrations); 21 structurally-uncomputable
  pivots were removed from the registry under the one-extra-call policy.
- A related drill that narrows to one resource opens its detail; circular
  drills reseed every stacked copy; the header keeps the version next to
  the depth badge.

### Fixes

- ebs, ebs-snap, dbc-snap: unencrypted / orphan / aged snapshots emit
  findings instead of coloring silently.
- elb: warn-level misconfiguration no longer renders as broken.
- opensearch: epoch-zero timestamps no longer fire the forced-update
  finding; encryption-at-rest is its own finding sentence.
- ec2 → IAM Role related pivot resolves the instance profile to its role.
- Availability sweep waits for AWS client readiness (no more "clients not
  initialized" on startup); the menu issue badge counts findings from a
  single source.
- CloudTrail event findings name their cause (failed call, root activity,
  destructive/modifying call, cross-account, sensitive read).
- ddb billing and cfn drift cells humanized.
