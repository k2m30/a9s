# v3.55.1 — Deleted resources stop haunting the session

A patch release closing two coupled defects found in live runs: 404s for
already-deleted resources polluting the `!` error log, and the disk cache
that kept manufacturing them. Verified by a 36-agent adversarial audit of
both issues before a line was changed.

## Error-log honesty (#456)

A resource deleted between the list call and a per-ID describe is an
operational race, not a failure. The S3 public-access-block enricher and
the Route 53 zone enricher now classify `NoSuchBucket`, bare `NotFound`
(S3's empty-body 404 synthesis), and `NoSuchHostedZone` as silent
data-incompleteness: the row gets its `?` marker, no finding is
fabricated for a resource that no longer exists, and nothing lands in
the `!` log. Genuine failures — 403, 5xx, transport errors — still
aggregate loudly.

The four S3 related-panel checkers (tags, encryption, logging, policy)
moved from message-substring guards to error-code classification and
treat a deleted bucket as an honest zero instead of an error cell. S3's
`SlowDown` throttle response is now retried instead of failing the call
on the first attempt.

## The cache stops resurrecting the dead (#457)

The per-type disk cache refused to drop rows even when an exact fetch
proved the resource gone — a deleted hosted zone's row re-seeded every
startup (on-disk `count: 22` against 23 rows) and fed the Wave-2
enrichment sweep a describe call against a deleted ID, reproducing the
404 noise each session until the type's list was opened.

An exact observation is now authoritative at the single disk-reconcile
chokepoint: stored rows shrink to the live population, and a population
that genuinely went to zero persists its emptiness. Truncated first
pages keep the older, deeper knowledge exactly as before; counts-only
sync-backs still never touch rows; carried Wave-2 findings and
`FindingFirstSeen` survive on the rows that remain. The cache contract
(`docs/design/cache-requirements.md` C6a) is amended accordingly and the
defect recorded as D18.

## For `core/` importers

New export: `core/aws.IsNotFoundErr`, the canonical
deleted-between-list-and-describe classifier. No breaking changes.
