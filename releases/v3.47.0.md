## Related Navigation That Always Resolves

### Every related row is navigable and honest

- The related panel's four-state row contract is enforced everywhere: an exact
  count `(N)`, a truncated lower bound `(N+)`/`(0+)`, a proven-zero dead end
  `(0)`, or a blank drill-in row. The ambiguous `(?)` is gone.
- A truncated row (`(N+)`/`(0+)`) is always navigable: Enter opens the scoped
  target list and keeps discovering matches as later pages load. `(0+)`
  behaves exactly like `(N+)` — the empty lower bound is not a special case.
- A truncated single-match pivot (`(1+)`) opens the scoped scan list and
  fetches the rest, instead of opening one detail and hiding the others.
- An errored related result is a dimmed dead end, never navigable; a
  fully-scanned empty population renders `(0)`, not a blank row; a scoreless
  drill-in row resolves its count in place rather than dumping the full list.

### One navigation path for the TUI and the web

- Related navigation now resolves through a single shared seed for both
  renderers: a filtered related list shows the same rows and issues the same
  fetch on the terminal and in the browser. This closes the cases where the
  web navigated a related row into an empty, stuck list with no fetch, and a
  cache-hit list whose targets were lazily fetched (by-ID) now renders its
  rows instead of appearing empty.
- A popped related list no longer leaks its scan filter onto later lists:
  after VPC → Security Groups, opening the plain Security Groups list is no
  longer wrongly filtered to the VPC's groups.

### Pivots resolve from event data — zero extra fetch to count

- CloudTrail-event, networking (nat/eni/rtb/igw), the RDS instance→cluster
  hop, and five forward IAM-role pivots now resolve their counts from data
  already in hand, with no extra list fetch.
- CloudTrail-event pivots resolve named targets by identity (never a scoreless
  `(0+)`) and drill into the correct role/target detail; blackhole route
  targets are skipped; secrets and ECR role pivots emit same-account role
  names, not ARNs; an IAM policy lazy-add resolves by name without listing the
  whole catalog.
- ACM certificates are keyed by ARN, so multiple certificates sharing one
  domain name no longer collide in the related panel.

### Findings, everywhere and complete

- Wave-2 enrichers emit a slice of findings per resource, so a resource with
  more than one problem surfaces each as its own Attention entry (OpenSearch
  shows both "update forced" and "encryption at rest off"); the Attention
  block is keyed by finding code.
- Child views join the findings-color doctrine: an unhealthy target colors
  itself and names its cause in lowercase; asg/ebs/logs wave-2 findings reach
  the row color. Web child lists color exactly like the terminal, and Enter
  opens child views from the browser.
- Issue badges are consistent: a list's title counts issues the same way as
  the menu badge (per resource, not per shared ID), the menu badge shows `+`
  when the count is truncated, and `~`-only enrichers no longer lower-bound
  the badge. Failed batches surface a per-row `?` or an error rather than
  silently under-counting.

### Detail view

- Tab focus lands on the first drillable related pivot; the viewport scrolls
  to follow the field cursor; nested CloudTrail REQUEST/RESPONSE values render
  as compact JSON instead of a raw `map[]` dump.

### Robustness

- The availability sweep waits for AWS client readiness — no probes against a
  nil transport on startup. Profile/region reads and writes share one lock so
  a switch can't race the availability save loop, and a cache store captures
  its directory at construction so a leaked save goroutine can never write
  into another root.

### Demo mode is a fuller verification bench

- Dozens of new demo witnesses fire on the bench — ecs-task, MSK, API Gateway
  and CloudFormation lifecycles, execution-history failures, and 34 more
  finding codes — so every color bucket and most related-panel pivots have a
  live demo witness.
