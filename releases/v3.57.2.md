# v3.57.2 — pivots stop reporting figures they did not earn

A patch on v3.57.1 from two external review passes over S3, CloudTrail,
EKS and node groups.

## Added

A bucket whose access control list grants a permission to anyone at all,
or to every signed-in AWS account, reports "publicly accessible", the
same broken-tier finding a public bucket policy reports, with a row
naming the group and the permission. A bucket that ignores public ACLs
does not report it; a bucket public both ways reports it once with both
rows. The account-level public access block is not read, and the finding
says so.

## Fixed

S3 pivots. A bucket row carries every notification destination, not the
first of each kind; a refused lookup reports the refusal and a
cross-region bucket shows "0+". The Route 53 row of a bucket and the S3
Buckets row of a zone agree on the join (the record name) and on
truncation. CloudFront and S3 match a bucket against the whole origin
hostname, so "my-assets" no longer appears on "assets" and a proxy host
is not a bucket. A CloudFormation stack with more resources than one
page shows "(N+)" for its buckets and rules.

CloudTrail events. The Principal row opens the IAM role for a direct
role ARN, and a role or user under an IAM path opens by its own name; an
ARN with no name is not offered as navigable. The TARGET of an event
with no resource record is the same on every viewing. The reason an
event was flagged travels with the row. The "CT events by SharedEventId"
pivot returns the sibling events instead of an error.

EKS and node groups. Two clusters with a node group of the same name
show two rows. A cluster's AMI and EC2 Instances rows count every node
group page and more than fifty scaling groups. The CloudTrail Events row
of a cluster counts only that cluster's own events.

The snapshot tool writes its file atomically and keeps its output
directory under `--out`.
