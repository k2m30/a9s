# v3.56.0 — o opens it in the AWS console

a9s is read-only by design, so the moment you find something to fix, the
next stop is the AWS console — previously via alt-tab, service search,
region picker, and a name filter. Now it's one key: `o` opens the
highlighted resource's exact console page in your browser; `O` copies
the URL for a ticket or a remote session.

## Coverage and verification (#477)

Every top-level type (70) and every child-view type (29) resolves a
deep link: lists, child lists, detail, and the focused related-panel
row. URL shapes were not guessed — each was captured live from AWS's
own `/go/view` ARN resolver (78 synthetic-ARN probes, including the
GovCloud and China console domains) and cross-checked against official
docs pages. That sweep corrected several assumptions along the way: WAF
now lives on the redesigned `wafv2-pro` routes with a scope parameter,
OpenSearch under `aos/`, ECS behind its own `ecs/v2/redirect`,
CloudFront on the documented v4 path, and ElastiCache serverless has no
deep link at all.

Per-type quirks are per-type config, not heuristics: global consoles
(IAM, Route 53, CloudFront, S3) skip the region subdomain, WAF's
CLOUDFRONT scope pins us-east-1, the `dbc` engine field routes Aurora
to RDS, DocumentDB to its own console, and Neptune to Neptune's (the
generic resolver would land it on RDS). Builders never emit a
wrong-but-plausible link: any missing required input yields a
"no console link" flash instead.

## One resolver, both renderers

Console-target resolution lives once, in the controller
(`Controller.ConsoleTarget`): list selection, detail resource, or a
focused single-target related row — resolved to the full cached row
when the session has one (new `Core.AnyLaneResourceByID`), else the
type's stub, else a bare ID that the hardened builders handle safely.
The TUI delegates to it and execs the opener; the web client reads
`data-console-url`/`data-is-demo` and opens/copies inside the keydown
handler. Neither renderer can drift from the other, and the server
never spawns a process.

The opener honors `$BROWSER` (whitespace-split argv — flags work,
quoting is not shell-interpreted), falls back to the platform opener,
reaps its child, and refuses any URL that fails the https +
console-domain allow-list. Demo mode never opens a browser; `O` still
copies. All environment variables — including this one and three that
were documented nowhere — now live on the wiki's Environment Variables
page, which README and the website point to.

## Review trail

Two Codex rounds (five findings: process reaping, cached-ELB link loss,
malformed related-row URLs, overlay keys swallowed, `$BROWSER` argv) —
each fixed with a regression test; a full self-review pass (two
hardening guards: empty-label console hosts, web-side URL validation);
a tmux smoke driving the compiled binary through `o`/`O` on list,
detail, help overlay, and clipboard; and a real-browser verification of
web mode. The busywork audit on this release's tests removed two dead
assertions (a `messages.Copied` branch that could never execute) in
favor of real clipboard readback.

## For `core/` importers

New: package `core/consolelink` (`Domain`, `Regional`, `Global`,
`GoView`, `AccountFromARN`, `Valid`, `Resolve`),
`catalog.ResourceTypeDef.ConsoleURL`, `app.Controller.ConsoleTarget`,
`app.ViewState.ConsoleURL`/`IsDemo` (JSON: `console_url`/`is_demo`),
`runtime.Core.AnyLaneResourceByID`. One removal inside the elb type:
the short-lived duplicate `Fields["arn"]` (never released) — the
long-standing `load_balancer_arn` key remains the single source. No
breaking changes.
