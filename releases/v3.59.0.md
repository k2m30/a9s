# v3.59.0 — every related count says what was read, in the Region that holds it

A release about the related panel: what each row counts, where it reads it,
and what it says when it could not read everything.

## Changed

Rows removed or relabelled. An Elastic IP no longer has a CloudWatch Alarms
row: no CloudWatch metric is keyed by an address or its network interface,
and the alarm on the instance behind the address is on the instance's row.
A DynamoDB table no longer has a Log Groups row, since DynamoDB writes no
log group. A security group's "Referenced SGs" row lists the groups this
group's own rules name. Secrets → CodeArtifact is labelled "CodeArtifact
Repositories".

## Fixed

Counts. A count is exact only when every place the link lives was read in
full. A place read in part, or one that could not be read beside rows found
elsewhere, makes it a lower bound `(N+)`; nothing read makes it unknown; and
`(0)` means everything was read and held nothing. Rows that used to read
`(0)` without reading anything now count or read unknown, and a list
restored from disk is read again before a row counts over it, so a restart
no longer turns an unread row into a zero.

Matching. A related row reads the field AWS records the link in instead of
guessing from names, counts every place AWS records it — dead-letter
targets, logging configurations, secondary sources, instance profiles, tag
selections — and no longer counts rows that stopped carrying the link, such
as a pending subscription, a terminated instance or a disabled destination.
Names match whole: a state machine running family `api-worker` is not
counted on the `api` service. EventBridge rules count on an ECR repository,
S3 bucket or ECS service when their pattern can match an event about it,
read the way EventBridge reads a pattern; a pattern a9s cannot read makes the
count a lower bound.

Contract sources. Each related row reads what `docs/related-resources.md`
names for it, and nothing it cannot hold: values such as a launch template's
`resolve:ssm:` image or an API Gateway stage variable are no longer counted or
shown as links, and a field naming another resource by ARN opens that row
for every resource type.

Regions. A detail opened on a row read in another Region reads that Region,
and so does everything opened from it — its YAML, a revealed secret, child
views, refresh, links, the console URL and its CloudTrail events. Resources
AWS keeps elsewhere are read where they are: a CloudFront certificate in
us-east-1, a pipeline action's resources in the action's Region, an ECS
task's `awslogs-region` log groups, a multi-Region trail's topic and key.
Two resources with one name in two Regions keep their own rows and findings.

Paging. Every paged read follows its pages to the end or says it stopped: IAM
groups and inline policies, Kinesis tags and Route 53 records past the first
page are read. A read that fails part-way keeps what it found as a lower
bound; lists built from two sources keep one source's rows when the other
fails and resume it on load more; a background refresh no longer shrinks a
list back to its first page. A related lookup that must make one call per
row of another type makes at most 50 and reads as a lower bound past that, so
opening a Lambda function no longer calls every API Gateway API in the
account.

ECR. The vulnerability counts are the newest image's, found by push time over
every image, and counted from the scan's findings; a repository too large to
read in full is marked not inspected.

Missing clients. A related row whose service the session has no client for
reads `?`, never an error; several panels used to show an error saying the
check panicked.

Demo. The demo account answers for the Fargate capacity providers AWS
creates in every account, so its Fargate cluster counts its Auto Scaling
group exactly, and each Beanstalk environment shows one name everywhere it
appears.
